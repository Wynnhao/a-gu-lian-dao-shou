## 1. 一句话概括

**LLM 是"读证据的综合分析师"，不是下指令的人**：系统每天把技术信号、新闻、宏观估值、市场环境、账户状态组装成决策输入包（bundle），LLM 基于包内证据输出结构化建议（买/卖/持有/观察 + 置信度 + 理由），再由 19 条硬规则的风控引擎裁决（含市场环境动态总仓位闸），人工闸门确认后模拟执行。任何一环证据不足或校验失败，当日安全降级为"只出报告不下单"。

当前策略基调：**截面量价打分（reversal_lowvol）为默认 profile、证据约束、小步建仓、市场环境定总闸**。依据与实况：

- 生产 score 用策略库 §2.1 口径（5日反转 0.40 + 低波动 0.35 + 低换手 0.25，池内截面 rank 合成）；
- **两个 profile 的样本内回测均未达标**（2026-09-13 可成交口径实测：momentum 年化 +35.5%/回撤 −32.2%，reversal_lowvol −8.0%/−36.2%，此前 v1.2 引用的 +25.84%/+54.95% 系"事后挑选票池+未复权+涨停可成交+无滑点"合成的虚高，不可信）；
  - 【更正说明（2026-09-21，W-D6 口径统一）】本条 +35.5%/−32.2% 为 2026-09-13 当时口径，权威口径以 2026-09-19 W-D6 重跑为准：momentum 年化超额 +17.98%、最大回撤 −47.78%、Calmar 0.376 → **FAIL**（reversal_lowvol −15.02%/−40.18%、v2 −1.41%/−25.27%，三 profile 全 FAIL，详见 §7 Sprint4 语义固化）；momentum 维持观察（ADR-Sprint4），观察期退出条款见本文 §7。
- signal 全史回填（18,946 样本）后的实证：score h5 RankIC +0.003（弱正），momentum_20d/RSI/换手 IC 为负——与研究先验一致但强度不足以证明超额；
- P6 模拟盘 4 周的验收主目标是**流程可靠性**（§5.5），收益只要求超额 ≥ −3%；
- profile 切换不靠手感，按 §7 的成文判据执行。

## 2. 决策包（bundle）构成与口径

盘前 9:00 由 `pipeline/premarket.py` 组装，落盘 `logs/session/<日期>/bundle.md|json`：

| 模块 | 来源 | 字段与口径 | 决策用途 |
|---|---|---|---|
| 技术信号 | `signal` 表（`signals/signals.py`） | ma_trend（MA5>MA20>MA60 多头 / 反之空头 / 其他震荡）、ma5/20/60、rsi_14（Wilder）、atr_14/atr_pct（全复权 OHLC 口径）、mom_5d/mom_20d（复权收盘收益率）、turnover_pct（自身 250 日分位）、turn20（近 20 日均换手）、above_ma60、close、pct_chg、price_basis/atr_basis（复权口径标注）、rev_clip/lowvol_clip（单票绝对水平参考） | 择时与方向；因子绝对水平参考 |
| 信号综合分 score | 同上 | reversal_lowvol（默认）：三因子**当日池内截面 rank**（min-max 归一 0~1）加权 0.40/0.35/0.25，缺因子重归一化，单票截面中性 0.5；score_parts 记录各因子 rank。momentum（旧，时序）：趋势 0.35 / 20日动量 0.40 / RSI 0.25 | 排序与初筛，score≠买卖指令 |
| 个股新闻 | 东财 `stock_news_em` 近3日 | 标题/来源/发布时间/正文摘要（bundle 内前120字） | 事件验证：要求 reasons 必须引用具体新闻或数据 |
| 市场新闻 | 东财全球快讯（新浪兜底） | 同上，code='' | 系统性风险感知 |
| 宏观估值 | `index_valuation`（乐咕乐股，上证为市场平均PE口径） | 沪深300/中证500/上证 的 PE、PE分位、PB、PB分位（0~1） | 仓位环境：估值极端分位时压低置信度 |
| 市场环境总闸 | `risk/regime.py` | RSRS z 分（000300，18日 H/L 回归斜率、600日标准分；>+1 满配 / <−1 避险 / 其余半配）+ 二八 20 日动量（000300 vs 000905，皆弱→避险）+ 波动率目标（组合年化波动 vs 30% 目标）→ **总仓位动态上限 cap** | 硬约束预告：全部买入 target_weight 合计 ≤ cap；卖出不受限 |
| 黑名单 | `risk/blacklist.py` | 上市<60日 / ST / 退市整理 → BLOCK | 硬禁买 |
| 数据健康 | `health_check` | 数据滞后、缺bar | 异常→当日 report_only |
| 账户状态 | `position` / `portfolio_state` | 持仓/可卖（T+1）/现金/总权益/回撤/kill_switch/**止损参考价（成本×(1−max(8%, 2×ATR占比))）** | 卖出可用性、仓位计算基数与止损纪律 |
| 近期决策 | `decision` 表 | 最近3条 action/status/confidence + 次日实际/方向反馈 | 避免反复打脸、保持决策连续性 |

### 口径纪律：多 profile 共表 + 双池分层（2026-09-13 错配修复）

`signal` 表主键是 `(code, as_of, profile)`——**同一票同一天在不同 profile 下各有一行**。因此所有读取方必须：

1. **按当前 profile 过滤**：唯一出口是 `common.config.active_profile()`（读 `config.signals.profile`，缺省 `reversal_lowvol`）。已收敛的读取方：`ai/bundle.py`（决策包）、`webapp/api/market.py`（看板信号接口）、`webapp/api/workflow.py` 与 `data_status.py`（流水线计数）、`review/signal_eval.py`（IC 评估，Fix-5 起）。**未过滤的后果**：决策包里同一只票出现两个 score（口径混淆），计数翻倍——修复前 bundle 实测存在该重复行。
2. **只放可交易池**：可交易池 = `config.watchlist_core`（当前 51 只：消费/AI/新能源/厄尔尼诺/苹果 各 10-11 只）；`config.watchlist_extended`（35 只：半导体/生物医药/政策军工/金融）**仅供看板与动态池观察，不可 buy/sell**。出口是 `common.config.core_codes()`，决策白名单（`ai/decide.py`）、回测 universe（`signals/backtest.py` 默认 `--universe=core`）、信号计算范围（`signals.compute_all(watchlist_only=True)` 默认）、异动池"自选池口径"（`signals/movers.py`）统一走它。
3. **回退与自证**：若决策日当前 profile 无行（刚切 profile 尚未重算），bundle 回退到当日行数最多的 profile，并在 `signal_scope` 里如实标注 `profile_fallback=true` 与 `requested_profile`；正常路径 `signal_scope` 记录 `{profile, pool, codes, dropped_non_core}`，便于事后核对决策包到底看了哪些票。

## 3. LLM 决策规则（写进输入包的"决策输出要求"）

1. 输出 JSON 数组，每条：`{action: buy|sell|hold|watch, code, target_weight∈[0,20%], confidence∈[0,1], reasons≥2条（必须引用包内具体数字/新闻标题/日期）, risk_notes, order?}`；buy/sell 必须带 `order{side, price, shares}`。
2. **价格纪律**：委托价 = 决策时点的最新价（盘前=昨收，午评=实时价，偏离实时价 >2% 会被风控拒）；**数量纪律**：100 股整数倍，单票金额 ≤ 总资产 20%。
3. **总闸纪律**：当日全部买入 target_weight 合计 ≤ regime 一节给出的总仓位上限；触及上限优先输出减仓/持有，不要加仓。
4. **置信度校准**：confidence 是"证据充分度"不是涨概率——有信号+新闻+宏观三重印证才 ≥0.7；只有单一证据 0.6 左右；证据矛盾或缺失 <0.6（会被自动降级为 report_only，不下单）。空仓观望输出 `[]` 是合法且鼓励的输出。
5. 黑名单票绝不交易；解析失败/校验失败 → **整包放弃当日决策**（原始输出落盘可修正重跑）。

## 4. 风控引擎裁决（19条硬规则，`risk/engine.py`）

LLM 建议只是"申请"，`check()` 逐条裁决，任何一条不过即拒：

| 类别 | 规则 |
|---|---|
| 禁入 | 黑名单；停牌/无行情 |
| 仓位 | 单票 ≤20%；**总仓位 ≤ min(80%, regime 动态闸)**；持仓数 ≤5 |
| 价格 | 委托价偏离实时价 >2% 拒；涨停不买、跌停不卖（主板10%/创科20%） |
| 频率 | 当日 ≤3 笔；周换手 ≤200% |
| 制度 | T+1（卖出 ≤ 可卖数量，当日买入不可卖）；100股整手（卖出清仓可零股） |
| 风控 | **单票止损线 = max(8%, 2×ATR占比)**：破线票禁止加仓（盘中扫描报告+通知，止损靠卖出执行）；同概念 ≤45%；下单 ≤ 当日成交额 1%；当日卖出禁止买回 |
| 时段 | 仅交易日 9:30-11:30 / 13:00-15:00 |
| 熔断 | 组合回撤 ≥8% → 强制清仓 + 停机 72h（kill switch，hold/watch 也触发评估）；清仓完成后回撤基准重置为清仓后权益（分段 8%，ADR-S4-1），全史 lifetime_peak/kill_count 持续观测 |
| 降级 | confidence <0.6 或数据健康异常 → report_only（当日只报告） |

动态总仓位闸（`risk/regime.py`，策略库 Top2/Top3 落地）三档语义：满配=静态上限 80%、半配=50%、避险=20%；RSRS 与二八取更保守者，再与波动率目标 cap 取 min，经 `build_context` 注入 `RiskContext.position_cap`。**该模块 fail-open**（计算失败不阻断交易，静态规则仍在）；kill switch 仍是 fail-safe 的最后一道。

裁决结果：`approved`（进闸门）/ `rejected`（违规留痕 risk_event）/ `report_only`。

## 5. 人工闸门与执行

- 闸门默认开（`config.execution.manual_gate=true`）：过审决策生成待确认单 `logs/orders/<日期>/pending_<id>.json`，**无人确认不下单**。
- 确认时**重跑一遍风控**（状态可能已变：到午休、价格 moved、额度用完、regime 档位变化），通过才由 PaperBroker 模拟成交：佣金 max(万2.5, 5元)、卖出印花税 5bp、滑点 10bps、T+1 记账，成交后回读校验账本一致性（不一致不置 executed 并留痕）。
- 执行层当前为 paper 模拟；同花顺实机 UI 自动化按 `execution/runbook_ths.md` 演练后才允许切 `mode=ui`。

## 6. 全链路工作流（看板"决策工作流"页的流水线）

**盘中节奏（v1.2 起，匹配 A 股上下午两次开盘）：**

| 时点 | 动作 | LLM | 说明 |
|---|---|---|---|
| 09:00 盘前 | 全量决策流水线（①→⑧），决策基于昨收+隔夜新闻 | ✅ | 现有 cron |
| 09:31 | propose-db 过风控，pending 单挂人工闸门 | — | 同一会话 |
| 11:35 午评 | 刷新实时行情+09:00以来新闻 → midday_bundle.md → LLM **增量复核**：默认输出 `[]`，仅 pending 单漂移>1.5% 或出现新证据时按新价/新证据出增量决策（旧单系统重提，仍走闸门） | ✅ 第2次 | cron（待建） |
| 14:50 尾盘扫描 | 纯脚本（pipeline/intraday_check.py）：实时回撤 kill 检查（触线即走引擎清仓+停机路径）+ **ATR 自适应止损扫描** + pending 单漂移预警 + 盘中快照留痕 | ❌ | cron（待建） |
| 15:30 盘后 | fetcher 正式入库当日日线 → 盯市 → 日报/周报 | ❌ | cron（待建） |

**实时行情口径（v1.2）**：交易时段内，风控价格保护、confirm 默认成交价、尾盘扫描、午评全部使用实时价（腾讯批量主源+东财兜底，30s TTL，快照审计到 logs/quotes/）；闭市或行情不可用自动回退日线收盘。**实时价绝不写入 daily_bar**，日线历史只归 15:30 盘后入库管。

十段流水线（⑩复盘前的状态由 /api/workflow 聚合，看板渲染）：

```
①行情采集 → ②资讯/估值 → ③数据体检 → ④信号计算 → ⑤输入包组装
→ ⑥LLM决策 → ⑦规则裁决 → ⑧人工闸门 → ⑨模拟执行(T+1/回读) → ⑩盘后复盘
```

每步的实时状态（时间戳、行数、通过/拒绝计数）由 `/api/workflow` 从 fetch_log/各表/文件系统聚合；午间增量决策与尾盘扫描产出的决策/风控事件会自然出现在当日追踪链里。

**机器漏开机的兜底机制（三层）**：

1. **多机制互备（Sprint4 W-D1 重建，2026-09-19）**：4 个交易日节点（9:00/11:35/14:50/15:30）为 ZCode 工作区自动化，第一步都跑 `pipeline/catchup.py`（幂等）；另有交易日 09:14 应急单兜底自动化（ZCode）+ 每 30 分钟 catchup 兜底与盘中每 5 分钟录制器（用户 crontab，`crontab -l` 可查）。旧的 launchd catchup plist 因中文路径编码+TCC 持续失败已移除（ADR-Sprint4 附记 C）。
3. **安全侧失效语义**：LLM 决策漏了就是漏了——当天没有决策 = 当天不交易（fail-safe，不自动伪造决策）。数据/盯市/报告/动态池全部可自动补齐；盘中决策补做路径：任意会话说"补今天的决策"（读补好的 bundle → decide.py --date → propose-db → 人工闸门）。

**失败语义**：①~⑤任何一步数据缺失 → 后续步骤 idle，⑦ 走 report_only；⑥ 解析失败 → 当日无决策；⑧ 拒绝/超时 → 不执行；⑨ 回读不一致 → 冻结等人工核查；14:50 扫描 kill 触发 → 立即清仓+停机72h（退出码 2 供调度告警）。整链不留"半执行"状态。

## 7. 证据闭环与 profile 切换判据（v1.5 起生效：B+C 两维投票 ≥1 票即建议 + MDD 红线 override）

数据链：`signal` 表已回填全史（2024-01 起逐日、逐票按当前代码口径重算，幂等可重跑：`.venv/bin/python3 /-m signals.signals --backfill`）→ `review/signal_eval.py` 输出 RankIC/五分位/滚动 IC/入池胜率 → 周报"信号有效性"章节引用 → 每次运行落盘 `logs/signal_eval/YYYY-MM-DD.json` + `latest.json`（任务 1），bundle.py 读取 latest.json 注入决策包，premarket 步骤 6.7 自动调用。注意：回填样本限于 daily_bar 票池（自选池 30 只事后挑选 + 中证800 回补数据），IC 结论带池偏差，只作相对比较不作绝对收益预期。

**profile 切换判据**（`review/signal_eval.profile_verdict`，周报自动输出建议，**仍由人工确认后改 `config.signals.profile`，系统不做自动切换**）：

## 8. 风控硬规则 · Sprint 1 增量（任务 4-5）

### 规则 20 · 因子拥挤度熔断（任务 5；Sprint 3 Fix-3 加滞回与权重降级）

`signals/signals.compute_all` 末尾按月分桶滚动 IC 算 `μ60 / σ60`，落盘 `logs/signal_eval/factor_crowding.json`。阈值：`μ60 < 0.005 且 σ60 > 0.02` → 拥挤。风控规则 20 读取 `crowded` 字段，**buy 单 target_weight > 5% 自动压回 5%**（按当前 equity 重算股数，整手规整）。sell 单不挡（拥挤熔断不该堵止损）。LLM prompt 增加规则 8：拥挤时 buy 需 confidence ≥ 0.7。

**Sprint 3 滞回状态机**（`_crowding_next_state`）：`off → active`（μ<0.005 且 σ>0.02，记 `active_since`）；`active → cooling`（μ≥0.015，计数 1）；`cooling → active`（μ 再跌破 0.005 清零回迁）；cooling 计满 5 次 compute_all 调用 → `off`；滞回带 [0.005, 0.015) 不翻转。`crowded = state in ("active","cooling")`（仓位压制在 cooling 期保留）。state 迁移写 `risk_event(rule='factor_crowding_state')`（同日同迁移去重）；计算不可用保留旧 state。

**拥挤权重降级（D2）**：`state=="active"` 时截面打分权重 0.40/0.35/0.25 → 0.20/0.20/0.15（重归一化到 1.0，改选股排序），`score_parts.crowding_downgraded=true` 供审计；cooling/off 用正常权重。与规则 20 的 5% 仓位压制双管齐下。

### 规则 21 · 跌停封单应急（任务 4）

A 股 T+1 + 涨跌停 + 隔夜跳空三重制度下，规则 14「卖价=跌停价拒卖」会让连续跌停持仓票卡死。规则 21 三条件 AND（条件② 缺数据静默跳过）：

- ① 卖单：`action=='sell'` 且 `order.price == limit_price(prev_close, limit_pct(code), up=False)`
- ② 死封（可选）：`ask1_vol * 100 / (float_mv / price) > 3%`，任一字段缺失视为通过
- ③ 浮亏 ≥ `stop_loss_line`（复用规则 16 现成实现）

触发动作：写 `risk_event(rule='limit_halt_emergency')` 一条；不直接下单（走 confirm 闸门由用户放行，plan 4.3 默认 A 路径）。规则 14 通过 `decision['emergency_pending_skip']=True` 同步豁免（**必须由规则 21 自己写**，普通 sell 单无法绕过）。

### 规则 21 主动扫描器 · confirm 优先 + 09:14 超时兜底（Sprint 3 Fix-4，D1 决策）

规则 21 原本只在 LLM 主动提交跌停价卖单时被动响应——LLM 不主动卖时连续跌停死锁依然成立。Sprint 3 落地主动扫描链路（`signals/limit_halt.py`，公共判定 `risk.engine._limit_halt_condition` 与规则 21 共用）：

| 时点 | 动作 |
|---|---|
| 盘后 postclose 步骤 3.5 | 对 position 表逐票判三条件（跌停价/封单比/浮亏≥止损线，T+1 不可卖票跳过；封单比条件②消费实时快照——Sprint4 W-A4 起按实测协议接线，未封死不生成）→ 命中生成 emergency sell 单（price=跌停价、shares=avail_shares、run_date=**次日**）→ `runner.propose` 入库（status=approved 挂 pending）→ macOS 通知 |
