# 决策策略与工作流（v1.2）

> 版本：v1.2 ｜ 2026-09-13 ｜ 本文档是看板「决策工作流」页的策略说明源文件
> 定位：说清楚每日决策包的依据、策略逻辑、裁决规则与全链路工作流

---

## 1. 一句话概括

**LLM 是"读证据的综合分析师"，不是下指令的人**：系统每天把技术信号、新闻、宏观估值、账户状态组装成决策输入包（bundle），LLM 基于包内证据输出结构化建议（买/卖/持有/观察 + 置信度 + 理由），再由 15 条硬规则的风控引擎裁决，人工闸门确认后模拟执行。任何一环证据不足或校验失败，当日安全降级为"只出报告不下单"。

当前策略基调：**动量为主、证据约束、小步建仓**。依据来自回测：2024-01 ~ 2026-09 对本池跑 20 日动量周调仓策略（双边成本 0.15%），年化 +25.84% vs 沪深300 +11.69%，最大回撤 -18.75%，动量在本池有正期望；敏感性和参数细节见 `logs/backtest_result.json` 与 `signals/backtest.py`。

## 2. 决策包（bundle）构成与口径

盘前 9:00 由 `pipeline/premarket.py` 组装，落盘 `logs/session/<日期>/bundle.md|json`：

| 模块 | 来源 | 字段与口径 | 决策用途 |
|---|---|---|---|
| 技术信号 | `signal` 表（`signals/signals.py`） | ma_trend（MA5>MA20>MA60 多头 / 反之空头 / 其他震荡）、ma5/20/60、rsi_14（Wilder）、atr_14、mom_20d（20日收益率，小数）、turnover_pct（换手率 250 日分位 0~1）、above_ma60、close、pct_chg（百分数） | 择时与方向：动量符号 + 均线结构定多空；RSI 30~70 为健康区 |
| 信号综合分 score | 同上 | 加权：趋势 0.35 / 动量 0.40（0.5+mom/0.30 截断）/ RSI 健康区 0.25，缺因子重归一化 | 排序与初筛，score≠买卖指令 |
| 个股新闻 | 东财 `stock_news_em` 近3日 | 标题/来源/发布时间/正文摘要（bundle 内前120字） | 事件验证：要求 reasons 必须引用具体新闻或数据 |
| 市场新闻 | 东财全球快讯（新浪兜底） | 同上，code='' | 系统性风险感知 |
| 宏观估值 | `index_valuation`（乐咕乐股，上证为市场平均PE口径） | 沪深300/中证500/上证 的 PE、PE分位、PB、PB分位（0~1） | 仓位环境：估值极端分位时压低置信度 |
| 黑名单 | `risk/blacklist.py` | 上市<60日 / ST / N开头次新 → BLOCK | 硬禁买 |
| 数据健康 | `health_check` | 数据滞后、缺bar | 异常→当日 report_only |
| 账户状态 | `position` / `portfolio_state` | 持仓/可卖（T+1）/现金/总权益/回撤/kill_switch | 卖出可用性与仓位计算基数 |
| 近期决策 | `decision` 表 | 最近3条 action/status/confidence | 避免反复打脸、保持决策连续性 |

## 3. LLM 决策规则（写进输入包的"决策输出要求"）

1. 输出 JSON 数组，每条：`{action: buy|sell|hold|watch, code, target_weight∈[0,20%], confidence∈[0,1], reasons≥2条（必须引用包内具体数字/新闻标题/日期）, risk_notes, order?}`；buy/sell 必须带 `order{side, price, shares}`。
2. **价格纪律**：委托价 = 决策时点的最新价（盘前=昨收，午评=实时价，偏离实时价 >2% 会被风控拒）；**数量纪律**：100 股整数倍，单票金额 ≤ 总资产 20%。
3. **置信度校准**：confidence 是"证据充分度"不是涨概率——有信号+新闻+宏观三重印证才 ≥0.7；只有单一证据 0.6 左右；证据矛盾或缺失 <0.6（会被自动降级为 report_only，不下单）。空仓观望输出 `[]` 是合法且鼓励的输出。
4. 黑名单票绝不交易；解析失败/校验不过 → **整包放弃当日决策**（不留半包）。

## 4. 风控引擎裁决（15条硬规则，`risk/engine.py`）

LLM 建议只是"申请"，`check()` 逐条裁决，任何一条不过即拒：

| 类别 | 规则 |
|---|---|
| 禁入 | 黑名单；停牌/无行情 |
| 仓位 | 单票 ≤20%；总仓位 ≤80%；持仓数 ≤5 |
| 价格 | 委托价偏离实时价 >2% 拒；涨停不买、跌停不卖（主板10%/创科20%） |
| 频率 | 当日 ≤3 笔；周换手 ≤200% |
| 制度 | T+1（卖出 ≤ 可卖数量，当日买入不可卖）；100股整手（卖出清仓可零股） |
| 时段 | 仅交易日 9:30-11:30 / 13:00-15:00 |
| 熔断 | 组合回撤 ≥8% → 强制清仓 + 停机 72h（kill switch，hold/watch 也触发评估） |
| 降级 | confidence <0.6 或数据健康异常 → report_only（当日只报告） |

裁决结果：`approved`（进闸门）/ `rejected`（违规留痕 risk_event）/ `report_only`。

## 5. 人工闸门与执行

- 闸门默认开（`config.execution.manual_gate=true`）：过审决策生成待确认单 `logs/orders/<日期>/pending_<id>.json`，**无人确认不下单**。
- 确认时**重跑一遍风控**（状态可能已变：到午休、价格 moved、额度用完），通过才由 PaperBroker 模拟成交：佣金 max(万2.5, 5元)、卖出印花税 5bp、T+1 记账，成交后回读校验账本一致性（不一致不置 executed 并留痕）。
- 执行层当前为 paper 模拟；同花顺实机 UI 自动化按 `execution/runbook_ths.md` 演练后才允许切 `mode=ui`。

## 6. 全链路工作流（看板"决策工作流"页的流水线）

**盘中节奏（v1.2 起，匹配 A 股上下午两次开盘）：**

| 时点 | 动作 | LLM | 说明 |
|---|---|---|---|
| 09:00 盘前 | 全量决策流水线（①→⑧），决策基于昨收+隔夜新闻 | ✅ | 现有 cron |
| 09:31 | propose-db 过风控，pending 单挂人工闸门 | — | 同一会话 |
| 11:35 午评 | 刷新实时行情+09:00以来新闻 → midday_bundle.md → LLM **增量复核**：默认输出 `[]`，仅 pending 单漂移>1.5% 或出现新证据时按新价/新证据出增量决策（旧单系统重提，仍走闸门） | ✅ 第2次 | cron（待建） |
| 14:50 尾盘扫描 | 纯脚本（pipeline/intraday_check.py）：实时回撤 kill 检查（触线即走引擎清仓+停机路径）+ pending 单漂移预警 + 盘中快照留痕 | ❌ | cron（待建） |
| 15:30 盘后 | fetcher 正式入库当日日线 → 盯市 → 日报/周报 | ❌ | cron（待建） |

**实时行情口径（v1.2）**：交易时段内，风控价格保护、confirm 默认成交价、尾盘扫描、午评全部使用实时价（腾讯批量主源+东财兜底，30s TTL，快照审计到 logs/quotes/）；闭市或行情不可用自动回退日线收盘。**实时价绝不写入 daily_bar**，日线历史只归 15:30 盘后入库管。

十段流水线（⑩复盘前的状态由 /api/workflow 聚合，看板渲染）：

```
①行情采集 → ②资讯/估值 → ③数据体检 → ④信号计算 → ⑤输入包组装
→ ⑥LLM决策 → ⑦规则裁决 → ⑧人工闸门 → ⑨模拟执行(T+1/回读) → ⑩盘后复盘
```

每步的实时状态（时间戳、行数、通过/拒绝计数）由 `/api/workflow` 从 fetch_log/各表/文件系统聚合；午间增量决策与尾盘扫描产出的决策/风控事件会自然出现在当日追踪链里。

**机器漏开机的兜底机制（三层）**：

1. **cron 互备（零配置，已生效）**：4 个定时任务（9:00/11:35/14:50/15:30）第一步都跑 `pipeline/catchup.py`（幂等）——当天只要任何一个 cron 跑到了，它先把此前漏掉的行情增量/历史盯市与日报/动态池/盘前 bundle 补齐。
2. **launchd 看门狗（已安装 deploy/com.agsickle.catchup.plist，需一次性授权）**：macOS launchd 语义——错过的定时触发会在唤醒后合并补跑一次（cron 做不到）。每 30 分钟尝试运行 catchup.py，无事秒退。**一次性授权步骤**：系统设置 → 隐私与安全性 → 完全磁盘访问权限 → "+" → Cmd+Shift+G 输入 `/Applications/Xcode.app/Contents/Developer/usr/bin/python3` → 打开。授权后看门狗自动生效（无需重装）。取消方式：`launchctl unload ~/Library/LaunchAgents/com.agsickle.catchup.plist && rm ~/Library/LaunchAgents/com.agsickle.catchup.plist`。替代方案：电源设置关掉自动睡眠，或 `sudo pmset -c sleep 0`，让 4 个 cron 天然全命中。
3. **安全侧失效语义**：LLM 决策漏了就是漏了——当天没有决策 = 当天不交易（fail-safe，不自动伪造决策）。数据/盯市/报告/动态池全部可自动补齐；盘中决策补做路径：任意会话说"补今天的决策"（读补好的 bundle → decide.py --date → propose-db → 人工闸门）。

**失败语义**：①~⑤任何一步数据缺失 → 后续步骤 idle，⑦ 走 report_only；⑥ 解析失败 → 当日无决策；⑧ 拒绝/超时 → 不执行；⑨ 回读不一致 → 冻结等人工核查；14:50 扫描 kill 触发 → 立即清仓+停机72h（退出码 2 供调度告警）。整链不留"半执行"状态。

## 7. 已知局限与演进

- 自选池已扩为 5 组概念股共 30 只（AI/厄尔尼诺/苹果/消费/新能源，见 config.json watchlist[].concepts），分散度改善但仍是小池子，动量回测数字（扩池后年化 +54.95%，样本内）不可外推——P6 模拟盘 4 周以"流程可靠性"为验收主目标（§5.5），收益只要求超额 ≥ -3%。风控上限不变：单票 ≤20%、总仓 ≤80%、持仓数 ≤5、当日 ≤3 笔。
- 日频收盘价成交是简化口径（真实盘前决策按开盘附近价格成交会有滑点）。
- 新闻目前未做情感量化，靠 LLM 引用原文而非打分。
- 演进方向见 `docs/策略库.md`（GitHub 开源与历年大赛策略的兼容度评估与 Top3 落地排序）。
