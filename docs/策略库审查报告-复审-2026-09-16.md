### P1-1 市场宽度模块 —— ⚠️ 走样（严重，公式级 bug）

**要求**：`breadth_composite` = 5 指标 250 日滚动 z-score 加权合成；`limit_up_seal_rate` = 封死/(封死+炸板)；`new_high_minus_new_low` = 60 日新高家数 − 新低家数；regime 第四档（composite < −2 → cap=0.1）。

**实现**（`data/breadth.py:203-240`）：

```python
# 简单 breadth_composite：z-score 加权（极简版）
composite = None
try:
    scores = []
    for col in ("limit_up_count", "limit_down_count", "advance_decline_ratio"):
        v = out.get(col)
        if v is None:
            continue
        # 250 日 rolling z（粗略：直接用绝对值，未来可加历史窗口）  ← 源码注释自证
        scores.append(v if col != "limit_down_count" else -v)
    if scores:
        composite = round(sum(scores) / len(scores), 4)
```

**问题清单**：
1. ❌ **公式错**：`composite = (limit_up_count − limit_down_count + advance_decline_ratio) / 3`，是**原始值算数平均**，不是 z-score；数量级几十（正常日涨停 40-80 家），与 `signals/breadth.py:54 threshold=-2.0` **完全不匹配** → regime 第四档"极端避险 cap=0.1"**几乎永远触发不了**（除非涨停=0 且跌停也很少），是**死代码**
2. ❌ **`limit_up_seal_rate` 硬编码 1.0**（breadth.py:66 注释"封板率不细分"），未算封死/(封死+炸板)
3. ❌ **`new_high_minus_new_low` 恒为 None**（breadth.py:95, 144, 168）→ 5 个指标里 **3 个是幌子**
4. ⚠️ `advance_decline_ratio` 依赖 akshare 列名"上涨"/"下跌"（breadth.py:81-83），列名一变即失效
5. ⚠️ **未接入 pipeline**：`grep compute_breadth pipeline/*.py` 零命中 → 日频不会自动更新

**数据源实现倒是完整**：三档兜底（em `stock_zt_pool_em` / tx 批量报价扫描 / sina HTML 正则），代码 252 行是本轮最重的模块之一，但**上层公式把它废掉了**。
