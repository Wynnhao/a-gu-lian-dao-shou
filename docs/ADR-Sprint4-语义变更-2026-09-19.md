## ADR-S4-1 · kill 回撤基准重置（"分段 8%"语义）

- **结论**（用户拍板 2026-09-19：接受）：kill（规则5，回撤≥8%）清仓完成后，回撤基准重置为清仓后权益（kill.json `dd_base`）；递延补清算场景由 `resolve_liquidations` 在"事件全清偿+持仓空"后补写（幂等）。
- **动机**：旧语义下一次真实 8% 回撤 = 永久停机死锁——清仓后 equity 恒比 250 行窗口峰值低 ≥8%，72h 到期或人工 resume 后下一次 check 立即重新 kill（审查报告 P1-1）。
- **全局口径不丢**：kill.json 同时累计 `lifetime_peak`（全史峰值）与 `kill_count`，日报/risk_event 持续观测累计口径，熔断史不静默丢失。
- **回撤口径统一**（随批）：daily 盯市（全史 clamp）/midday/intraday（250 行窗口）三处统一为 `effective_peak()` 单一定径（dd_base 感知窗口+clamp），消除"报表说破线、引擎不 kill"。
- **反方论点**：分段后每段独立 8% 理论上放大累计回撤容忍度。对冲：lifetime_peak 观测 + kill_count 留痕 + 人工可随时依全局口径干预。
- **替代方案**：不重置基准、kill 后冻结至人工 reopen（更保守，每次 kill 需人工解锁）——被拍板否决。
- **落点**：`execution/runner.py`（write_kill_state 合并式原子写 / effective_peak / _do_kill / resolve_liquidations）、`data/repo.py`（peak_total after 参数）、`review/daily.py`。

## ADR-S4-2 · 涨停判定取整改用交易所口径（market.py 红线5 废止）

- **结论**：`backtest._limit_up_price` 弃用裸乘积，改 `common.market.limit_price`（Decimal HALF_UP 到分）。`market.py` 原"红线5"（保留裸乘法避免微变 tradable 边界）**废止**。
- **新事实**：真实停板价=round(prev×(1+pct),2)；裸乘积向下取整时约 38% 的真涨停收盘被漏判为"可买"，在 full 宇宙上单独贡献约 +14pp 年化虚高（Sprint4 审查 P0-3 实测）。原红线保的是错的边界。
- **反方论点**：取整会微变回测 tradable 边界、新旧结果不可直接对比。接受——回测结论本就随数据版本重跑（W-D6 元数据 `limit_rounding=exchange` 固化）。
- **落点**：`signals/backtest.py`、`common/market.py` 注释、新 `logs/backtest_result.json` 元数据。

## ADR-S4-3 · backtest MDD 红线=评估信号，非交易禁令

- **结论**：红线触发（当前 profile 回测 MDD < −30%）语义固定为：**降置信 + 需更强证据 + 避险档/拥挤上限内可小仓位试探**；不得解读为"无条件不新开仓"。bundle 提示词规则 10/11 固化，并新增"当前可行动空间"节把硬边界显式算给 LLM；红线引用必须带 backtest 数据版本（缺失时按"无红线信息"处理并注明，严禁臆造数字）。
- **动机**：09-18 动量日（全市场涨停 78 只）AI 把红线误读为交易禁令全程空仓（审查 P1-26）；文档原文本就写明"不直接切断交易"（决策策略 §7:135），但 LLM 输入包无此澄清。
- **反方论点**：放宽解读可能让 LLM 在红线期冒进。对冲：硬边界（regime cap/拥挤 5%/黑名单）不变，红线仍优先压置信。
- **落点**：`ai/bundle.py`（_OUTPUT_RULES 10/11、verdict 渲染、actionable_space）。

## 附记 A · qfq 复权口径裁决（W-B4 验收口径重校准）

W-B4 验收不变量（"qfq 单日跌幅深于 raw >0.3pp ⇒ 脏数据"）在实施中被证伪为**乘法型专属**：实测 akshare 的 em_qfq/tx_qfq 均为加法型（d=close−close_qfq 仅在除权日台阶），加法型在非除权日 qfq_ret≡raw_ret，低股价×大额累计分红票（如 600096：4.1 元−3.79 元调整后≈0.31 元做分母）历史段收益被源算法固有放大（2024-01-22 raw −5.5% vs qfq −7.28%），**属源算法特性非管道缺陷**（与源逐值核对一致）。真正结构性目标已达成并固化：单票整段单源（em_qfq/tx_qfq 绝不混源）+ fetch_log 源标记 + 增量锚点漂移检测自动全史重刷（永久闸）。统一复权算法口径维持"明确不做"（计划 §明确不做 第 1 条），W-D6 回测元 data_version 已注明该风险，跨源/跨期读数须知。原审查报告 P1-11 的"315 行污染"机制定性据此修正（后果同向：因子层扭曲存在；根因是口径而非锚点混写）。

## 附记 B · profile 选型重跑结论（W-D6）与处置拍板

- **重跑口径**：full 816 宇宙（C-TEST-5 达标）+ 交易所取整（ADR-S4-2）+ momentum 与生产同源打分（0.35 趋势+0.40 mom20+0.25 RSI）+ IVOL 日期对齐/样本矩 ddof=1/turn20 min_periods=10（P2-2/3/4 前置）+ qfq 口径见附记 A。窗口 2024-01-02→2026-09-17（657 交易日）。
- **结果**：momentum 年化 +17.98%/MDD −47.78%/Calmar 0.376 **FAIL**（旧 core 口径 1.126 pass 系幸存者偏差+涨停漏判+异源打分合成，P0-3 实证）；reversal_lowvol −15.02%/−40.18% FAIL；reversal_lowvol_v2 −1.41%/−25.27% FAIL。三 profile 全不过，momentum 破 −30% 红线（verdict=hold 评估信号，按 ADR-S4-3 语义执行）。
- **拍板**（用户 2026-09-19）：**维持 momentum 观察期**，不回退 reversal_lowvol（其 pass 同样不成立且更差）；红线按评估信号语义运行；切换判据继续走 §7 证据闭环人工确认。
- **护栏**：pass=true 硬性要求 universe==full（core 跑 pass=null）；`logs/backtest_result.json` 元数据固化（universe/window/generated_at/data_version/limit_rounding/momentum_scoring）；旧 core 产物已退役为 `.invalid`。
- **反方论点**（2026-09-21 追记，09-21 全库对抗审查 P0-B；"空仓直到有 profile pass"方案当初被否决的理由）：①机会成本——三 profile 全 FAIL 是 W-D6 回测口径下的结论，momentum 是其中唯一正年化（+17.98%）、唯一跑赢基准者，回退 reversal_lowvol 无数字支持（更差）；全空仓等于把唯一的正期望候选一并放弃，也放弃 ADR-S4-3"红线=评估信号"语义下避险档/拥挤上限内小仓位试探的可行动空间。②空仓也是仓位——100% 现金隐含"市场将跑输现金"的判断，市场上行期空仓相对基准的超额必然持续为负，空仓方案同样有方向性敞口，并不比"维持"更中性。③在无新证据时以"感觉更安全"推翻既有拍板，本身就是判据购物（用偏好替代成文判据）。对冲现状：账户本就 100% 现金+人工闸门，经济风险趋零，"维持"的内核是理性的——不理性的是"维持+红线棘轮+无退出条件"的叠加（见下条替代方案）。
- **替代方案**（2026-09-21 追记；数值待用户拍板）：①（当初被否决）立即空仓、直到有 profile 在 W-D6 口径 pass 才复仓——否决理由见上条反方论点；②（折中，本次预注册建议稿）维持 momentum 观察期 + 预注册退出条款：W+4 周（建议 2026-10-19）重跑 W-D6 口径仍 FAIL，或生产可实现超额<X 连续 N 日 → 停用 profile、空仓等研究线；退出机械执行、触发即执行不再重新辩论，详见 `docs/决策策略与工作流.md` §7 观察期退出条款；③（更保守）红线期直接停用全部 profile 交易通道——与 ADR-S4-3"红线=评估信号非交易禁令"语义冲突，未采纳。

## 附记 E · 应急卖单执行日跌停价口径与跨周 run_date（P2②③，全量打包批 2026-09-20，批次4a）

- **P2② 行为变化**：实时价缺失时应急卖单（emergency_scan）按显式设计价执行的口径，从"T 日跌停价原样执行"改为 **min(设计价, 执行日跌停价)**——T+1 继续死封时 T 日跌停价高出真实可排队价 ~11%（10% 板；20% 板 +25%），按设计价成交即幻影价成交；执行日跌停价（基准=ctx.prev_close，与规则14/paper 停板防线同口径）才是"次日 09:15 集合竞价挂跌停价"的正确落点。连续死封=真实排队价；开板=保守低估（真实成交价只会更高，反向保守性质保持）。kill_liquidation 设计价=最新收盘（无跌停排队前提），维持原口径不套用。
- **P2③ 行为变化**：应急单预期执行日从"自然日次日"改为"自然日次日遇周末顺延到周一"（`signals/limit_halt._next_exec_date`）——周五盘后单不再落 run_date=周六（周一 09:14 failsafe 查不到+跨日闸拒，连续跌停退出晚 3 天）。法定节假日仍由 premarket"run_date=今天才执行"语义自然顺延，不引入交易日历依赖（盘后时刻节后首交易日未必已入日历缓存）。
- **P2④ 非语义**：删除从未被消费的 `_explicit_price` 死标记（接线反而会打开 --price 绕过执行价二次校验的口子，F1b 语义不变）；挂起/拒执单补主动通知（notify），行为只增不删。
- ①⑥（effective_peak 回放守卫+dd_base 分段窗口）为口径修正非语义变化：回放守卫消除"补跑历史日报回撤被覆写为 0"的数据污染；分段窗口与无 dd_base 分支的 250 行窗口语义对齐（ADR-S4-1"dd_base 感知窗口"原意）。⑤为观测接线非语义变化：日报补熔断史累计行，kill.json 缺累计键时无此行。
- 反方论点（②）：执行日跌停价在开板日会以低于市价的价格成交申报。接受——应急单语义本就是"集合竞价挂跌停价排队卖出"，开板时实际成交价由市场决定且只会更有利；幻影高价单才是真风险（被价格保护/规则14 拒或虚增成交）。

## 附记 D · 有痕降级日自愈与 PENDING 清除收窄（P2⑬/⑲，全量打包批 2026-09-20，批次4c）

- **P2⑬ 行为变化**：`catchup._mm_done` 新增愈合分支——portfolio_state note 含「价格滞后:」且**滞后代码中至少一个在该交易日已有 daily_bar 行**时，判"盯市未完成"（此前一律算完成）。效果：`postclose --date 今日` 在当日日线未出时的降级盯市（有痕，W-D3），当晚数据到位后 catchup 步骤4 会重跑 postclose 完成自愈（此前无任何节点重跑，当日 state/日报永久停在滞后价）。不触发重跑循环的边界保持：滞后代码仍全数无该日 bar（真停牌）→ 算完成；愈合重跑后 note 按最新数据重写，每波数据到位至多重跑一次（W-D2 P1-16 防循环语义不变；`conn=None` 旧调用形态亦维持旧语义）。盯市成功+日报失败当日不自愈（次日 catchup 步骤1 补）仍为 W-D2 刻意收窄，未改（P2⑳ 留档确认）。
- **P2⑲ 行为收窄**：`postclose` 成功尾部的"清今日 PENDING"从无条件改为**仅当本次成功跑的就是今日**（trade_date==今天）才清——`--date 补历史` 成功不再误删今日 PENDING 提醒物（今日 daily_bar 仍缺时该文件必须保留）。清除逻辑下沉为 `_clear_pending_today()` 供测试直调（同时修复 P2⑱：旧测试自己 unlink stub 的同义反复）。
- 反方论点：⑬的愈合分支让 catchup 在数据迟到晚会多跑整套 postclose（含 fetcher/体检/扫描）。接受——与 W-D2 之前的步骤4 重跑同量级，且随数据齐备收敛；换来的是降级日 state/日报最终与真实收盘一致。
- 落点：`pipeline/catchup.py`（`_mm_done`/`_stale_codes_from_note`/步骤4 调用与注记）、`pipeline/postclose.py`（`_clear_pending_today`）。
