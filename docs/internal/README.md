# 内部归档说明

本目录是项目从立项到 v1.3 公开版本的**研发过程留档**。这些文档面向：

- 项目维护者做历史决策回溯
- 贡献者理解某些设计选择的背景与权衡
- 第三方研究者复现项目演进过程

**不建议**：首次接触项目的人从这里读起——文档中大量内部代号（批次 0/1/2/3、Sprint 1/2/3/3.5/4、W-A/B/C/D、P0/P1/P2、C-ARC、C-STR、C-ENG）、AI 协作术语（对抗式审查 / 多 agent 验证 / 预注册 / 判据冻结 / fresh-context）会显著提高阅读门槛。

## 目录结构

```
docs/internal/
├── README.md              ← 本文件
└── archives/              ← 归档的 21 份历史文档
    ├── 批次报告系          ← 数据/研究线的批次执行报告（5 份）
    ├── 多 agent 审查系     ← 多 AI 代理对抗审查记录（4 份）
    ├── Sprint 计划系       ← Sprint 阶段计划与完工报告（6 份）
    ├── 施工方案系          ← 各类施工方案（C-ARC、qfq、缠论 R3 等）（5 份）
    └── ADR-0              ← 执行失败分类法 ADR（1 份）
```

## 文档命名约定

- `批次N-<主题>报告-YYYY-MM-DD.md` — N 是批次编号（0~7），反映研究/施工执行的次序
- `SprintN-<类型>-YYYY-MM-DD.md` — Sprint 编号 + 文档类型（修复计划 / 实施计划 / 审查报告 / 完工报告 / 复审报告）
- `多agent全库审查报告-YYYY-MM-DD.md` — 多 AI 代理并发审查的全库审计报告
- `<代号>-<主题>-YYYY-MM-DD.md` — 具体施工/方案/借鉴文档（C-ARC 架构加固、qfq 等比口径、缠论 R3 等）
- `ADR-<编号>-<主题>.md` — 架构决策记录（Architecture Decision Record）

## 阅读建议

如果你真的需要翻阅：

1. **先看** [`决策策略与工作流.md`](../决策策略与工作流.md) 与 [`代码审查报告.md`](../代码审查报告.md) 建立项目全貌
2. **再回到这里**查具体决策的背景
3. **遇到内部代号**（W-A2、P0-B、批次 4 等）可对照 CONSTRAINTS.md 的 L1~L4 体系理解

## 贡献约定

- 本目录的文档**不再更新**——它们是历史快照
- 如发现文档内容与代码严重不符，请直接更新 [`../决策策略与工作流.md`](../决策策略与工作流.md) 等核心文档
- 新增 ADR 时建议用 `docs/ADR-<新编号>-<主题>.md` 命名（不再放 archives/）

如对归档策略有建议，欢迎在 Issue 里讨论。
