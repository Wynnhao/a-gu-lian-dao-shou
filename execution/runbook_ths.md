# Runbook：同花顺PC客户端 模拟炒股 UI 自动化操作手册（computer-use 逐步执行版）

> 适用对象：在 ZCode 会话中操作同花顺PC客户端"模拟炒股"的 computer-use agent。
> 前提硬约束：`config.json` 的 `execution.mode` 必须为 `"ui"` 才允许进入 UI 模式；
> `"paper"` 模式一律走 `execution/runner.py`，不得操作真实客户端。
> 本手册全部操作仅限**模拟炒股账户**，绝不触碰实盘资金。

---

## 0. 前置检查（每次会话开始，全部通过才能继续）

- [ ] **R0.1 模式检查**：读取项目 `config.json`，确认 `execution.mode == "ui"`。
      若为 `"paper"`：**中止**，改用 paper 引擎（`python3 execution/runner.py ...`），不要打开交易界面。
- [ ] **R0.2 客户端状态**：确认同花顺PC客户端已启动，且已登录**模拟炒股**账号
      （交易面板显示的是模拟账户，通常标注"模拟"字样）。
      未登录 → **中止**并提示人工登录；绝不代填真实账号密码。
- [ ] **R0.3 时段检查**：确认当前为 A 股交易时段（周一~周五 09:30-11:30 / 13:00-15:00）。
      非交易时段 → **中止**（对应风控规则4，UI 模式同样不许下单）。
- [ ] **R0.4 待办单检查**：读取 `logs/orders/<当日>/pending_*.json`（人工闸门产出的待确认单），
      逐条按本手册第 3 节执行；无待办单则本会话不做任何下单。
- [ ] **R0.5 截图目录**：创建 `logs/shots/<当日>/` 目录，本会话所有截图存此处。

---

## 1. 每次会话固定步骤：持仓对账（先于任何下单）

- [ ] **R1.1 截图持仓页**：进入"交易 → 持仓/查询持仓"页面，整页截图，
      保存为 `logs/shots/<date>/step1_position.png`。
- [ ] **R1.2 读取本地镜像**：读取本地 `position` 表镜像（可通过
      `python3 execution/runner.py status --date <date>` 的"账户/持仓"段获取
      代码/持股/可卖/成本，或直接读 SQLite）。
- [ ] **R1.3 逐票核对**：对照截图与本地镜像，核对每只票的 代码、持股数、可卖数量：
      - 完全一致 → 对账通过，继续第 3 节；
      - 差异在阈值内（任一票数量差 ≤ 100 股，或仅成本价小数差异）→ 记录差异到会话输出，
        标注"对账通过（有噪声）"，继续；
      - 任一票数量差 > 100 股、或截图有本地没有的持仓/本地有截图没有的持仓 →
        **中止并告警**：打印差异明细，提示"先人工对账"，本会话不再执行任何下单。
- [ ] **R1.4 对账留痕**：把 R1.3 的结论（一致/差异明细）写进会话输出；
      若后续有成交，成交后需重跑一次本节复核（见 R3.8）。

---

## 2. 界面导航约定（元素定位规则）

- [ ] **R2.1** 优先用界面上的**文字标签**定位（如"买入""卖出""委托""成交"按钮文字），
      其次用相对位置描述；禁止凭猜测点击无文字的图标区域。
- [ ] **R2.2** 每次点击/输入后等待界面刷新（约 1 秒）再进行下一步；
      出现加载中/卡顿 → 再等待，连续 2 次无响应按中止条件处理。
- [ ] **R2.3** 任何**弹窗**出现：先整窗截图并读出全部文字。
      - 弹窗内容可识别且与当前操作相符（如"委托确认"）→ 按第 3 节流程处理；
      - 弹窗内容**未知/无法解析/含账户设置、密码、实盘字样** → **立即中止**（不点任何按钮，
        截图 `logs/shots/<date>/abort_popup_<ts>.png`），交人工处理。

---

## 3. 下单步骤（每条 pending 单严格走一遍）

以下以一条 pending 单为输入：
`logs/orders/<date>/pending_<decision_id>.json`（内含 `decision`、`submit_price`、`suggest_shares`）。

- [ ] **R3.1 进入下单页**：交易 → "买入"（decision.action=buy）或"卖出"（action=sell）。
- [ ] **R3.2 输入代码**：在代码输入框输入 `decision.code`（6位数字），等待关联出股票名称，
      截图 `logs/shots/<date>/r1_code_<decision_id>.png`，
      **核对**显示名称与 pending 单/本地 stock_info 名称一致；不一致 → 中止该单。
- [ ] **R3.3 输入价格**：在价格框输入 `submit_price`（= `decision.order.price`，两位小数）。
      **禁止**改用市价/对手价/最新价等其他价格来源；价格只能来自 pending 单。
- [ ] **R3.4 输入数量**：在数量框输入 `suggest_shares`。
      卖出时数量不得超过界面显示的"可卖数量"（若界面可卖 < suggest_shares → 中止该单并告警）。
- [ ] **R3.5 提交前核对截图**：填完后整页截图 `logs/shots/<date>/r2_review_<decision_id>.png`，
      逐字核对界面上：代码、买卖方向、价格（== `decision.order.price`）、数量（== `suggest_shares`）。
      **四项全部一致才允许点"提交/下单"**；任何一项不一致 → 修单重填或中止该单，绝不提交。
- [ ] **R3.6 提交委托**：点击"提交/下单"；若弹出确认框且内容与刚才核对一致 → 确认。
      截图提交后回执 `logs/shots/<date>/r3_submitted_<decision_id>.png`。
- [ ] **R3.7 委托回读**：进入"委托/当日委托"页，截图 `logs/shots/<date>/r4_orders_<decision_id>.png`，
      找到该笔委托：核对 代码/方向/价格/数量/状态（已报、部成、已成）。
- [ ] **R3.8 成交回读**：进入"成交/当日成交"页，截图 `logs/shots/<date>/r5_deals_<decision_id>.png`：
      - 已成交（全部成交）→ 记录成交价格与数量；与 `decision.order.price` 偏差 > 2%（price_guard_pct）
        → 告警并标注，交人工复核；
      - 未成交/部成 → 如实记录状态，不得撤单重挂（撤单属人工决策）；
      - 回读后重跑第 1 节持仓对账（R1.1~R1.4）确认本地镜像与界面一致。
- [ ] **R3.9 回写 trade.shots**：把本单产生的截图路径按顺序写入 `trade.shots`
      （JSON 数组字符串，如 `["logs/shots/2026-09-14/r1_code_3.png", "..."]`）。
      paper 模式该列为 `"[]"`；UI 模式必须非空。写入方式：由执行层脚本更新对应 trade 行，
      computer-use agent 只负责收集路径列表并在会话输出中给出，不直接改库。

---

## 4. 截图与留痕约定

- [ ] **R4.1** 每一步截图保存到 `logs/shots/<date>/`，文件名含步骤编号与 decision_id（见第 3 节）。
- [ ] **R4.2** 每单完成后在会话输出中列出该单全部截图路径（供 R3.9 回写）。
- [ ] **R4.3** 中止/异常时的截图同样保存，并在会话输出中给出原因与最后一步操作。

---

## 5. 中止条件清单（任一命中立即停止，不再下单）

- [ ] 任一界面元素定位失败 **2 次**（含按钮、输入框、页签）；
- [ ] 出现**内容未知**的弹窗（按 R2.3 处理后仍无法确认）；
- [ ] 提交前/回读时**价格核对不一致**（界面价 ≠ `decision.order.price`）；
- [ ] **非交易时段**（含午休 11:30-13:00、收盘后、周末节假日）；
- [ ] 持仓对账差异超阈值（第 1 节 R1.3）；
- [ ] 界面可卖数量 < 卖出委托数量；
- [ ] 客户端断线、行情中断或界面长时间（>2 次等待）无响应；
- [ ] pending 单中 decision 缺少 `order.price` 或 `order.shares`（数据不完整）。

中止后动作：截图现场 → 会话输出"中止原因 + 已完成步骤 + 待人工介入事项" → 结束本会话 UI 操作。

---

## 6. 禁止事项（红线，任何情况下不得违反）

- [ ] **绝不点击"实盘/真钱/正式交易"等任何真实资金入口**；只使用模拟炒股入口。
- [ ] **不修改任何账户设置**（密码、手机号、银行卡、风险等级、银证转账等一概不碰）。
- [ ] **不使用异常价格**：委托价必须等于 `decision.order.price`（来自 pending 单），
      不得使用市价单以外的限价改价、对手价、涨停价扫单等自创价格；
      也不得提交市价单——一律限价单。
- [ ] **不撤单、不重挂**：委托后未成交不自动撤单（人工决策）。
- [ ] **不代填真实账号/密码/验证码**。
- [ ] **不在风控未通过（decision.status 非 approved）的情况下下单**。
- [ ] **不直接修改数据库**：computer-use agent 只收集截图路径，trade.shots 由执行层脚本回写。

---

## 7. 单次会话操作顺序总览（速查）

```
[前置 R0.1-R0.5 全过]
        │
[第1节 持仓对账 R1.1-R1.4 通过]
        │
逐条 pending 单:
  R3.1 下单页 → R3.2 代码(核对名称) → R3.3 价格(=order.price)
  → R3.4 数量(≤可卖) → R3.5 提交前核对截图(四项一致才提交)
  → R3.6 提交 → R3.7 委托回读 → R3.8 成交回读+持仓复核
  → R3.9 收集截图路径回写 trade.shots
        │
[会话结束: 输出全部截图清单与成交汇总]
```
